# MITRA NIDHI CHITI PRO Finance Engine

## Workflow

Finance data is generated by the chit lifecycle and consumed by the existing Finance & Accounts route.

```text
Collection
-> Cash / Bank Entry
-> Receipt Entry
-> Income Register
-> Commission Register
-> Profit Update
-> Ledger Update
-> Dashboard Update
-> Reports Update
-> Activity Timeline
-> Notifications
```

The UI consumes `src/services/financeService.js`; it does not calculate balances or profit inside React components.

## Accounting Rules

- Collection entries become income and cash/bank rows.
- Cash modes update cash book.
- UPI, cheque, online and bank transfer modes update bank book.
- Auction commission is calculated by `CommissionEngine`.
- Profit is calculated from income, expense, commission and pending collection.
- Day closing compares income, expense and closing balance.
- Month closing exposes net-profit status.
- Export-ready rows are generated in the service layer.

## Ledger Flow

`LedgerEngine` builds ledger rows from:

- Finance repository entries.
- Collection entries.
- Receipt references.
- Debit and credit movement.

The ledger model exposes journal rows and a trial-balance-ready validation status for future production accounting expansion.

## Validation Rules

Validation lives in `src/domain/finance/validators/AccountingValidator.js` and is exported through `src/domain/finance/FinanceValidator.js`.

Rules covered:

- Duplicate transaction.
- Negative balance.
- Invalid transaction.
- Missing ledger.
- Invalid payment mode.
- Invalid date.
- Closed month protection.
- Balance mismatch.

## Known Limitations

- Local repository storage is still the active persistence layer; Supabase can attach behind repositories.
- Trial balance remains future-ready and is not a full statutory accounting close.
- Day/month close records are calculated views today; immutable close posting can be added behind the service.
- Export is CSV-ready from browser data; server-side signed exports can be added later.
